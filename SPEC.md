# DEXQ — фактическая спецификация технического MVP

## Назначение и пределы

DEXQ локально проверяет качество нативных обезличенных DXA-изображений до интерпретации специалистом. Это исследовательский инструмент, не диагностическая или клинически валидированная система. Единственный источник текущего runtime — оптимизированный архив `dxa_qc_with_models (2).zip`, SHA-256 `b92ed6e89b1bb54358b1e06681842dbecac006880cf9062ea68980673ff12f0a`; его 74 Python-файла сохранены побайтово, модели поставляются отдельно вне Git. Медицинские данные и производные изображения не передаются наружу.

## Входы, маршрут, проверка

- Поддержаны одноканальные 8-bit `MONOCHROME2` DICOM и для технической демонстрации grayscale PNG; JPEG runtime не принимает. Область выбирается автоматически router-моделью (`lumbar_spine`/`proximal_femur`) или явно оператором. Для бедра сторона определяется отдельной моделью; **не** по названию снимка. API считывает явный DICOM `ViewPosition=AP/PA` как `projection=AP/PA` с источником `dicom_view_position`; при отсутствии тега выдаёт `unknown`/`not_determined`, а явный иной `ViewPosition` вызывает управляемый отказ. Определения AP/PA по пикселям нет.
- Позвоночник: `spine_positioning` — нижнее яркостное и верхнее gap-sequence **эвристические** правила, `spine_axis` — два обнаруженных SpineNet-центра и угол относительно вертикали с порогом строго `>5°`, `spine_artifacts` — ResNet18-признаки с числовым классификатором. Бедро: `hip_positioning_rotation` — **общий** флаг без отдельного различения ротации и укладки; `hip_roi` — классификация охвата без анатомической ROI-маски и без физического измерения запаса поля. У бедра нет редактируемых анатомических точек.
- Любое применимое нарушение даёт класс `1`, полное отсутствие нарушений — `0`. Если обязательная проверка не определена, статус `Failure`, класс `null` в JSON или пустое поле в CSV. `needs_review` выводится отдельно от итогового решения. Оператор может передвинуть только две реальные точки оси spine: ручная оценка/CSV отдельно и не меняет исходный ML-ответ, сервер правки не хранит.

## API и пакеты

`GET /api/v1/health` возвращает готовность после проверки/загрузки локальных моделей или 503; `GET /api/v1/checks` даёт каталог пяти проверок. `POST /api/v1/analyses` — один снимок, неразбираемый вход → 422. `POST /api/v1/analyses/batch` и `/batch.csv` принимают 1–200 файлов и сохраняют успешные ответы при частичной ошибке; `/archive` и `/archive.csv` обрабатывают ZIP до 200 изображений с ограничениями размера/путей. UI поддерживает такой же лимит и показывает ZIP-результат через JSON; CLI принимает локальную директорию/ZIP. Одна CSV-строка на входное изображение, в порядке архива; четвёртый и последующие кадры одного Study UID тоже обрабатываются, но гарантии времени для больших исследований не заявлены. Имена в JSON и ошибки санитизируются; CSV для ZIP сохраняет входные относительные пути, поэтому публиковать его нельзя, если исходные имена содержат чувствительные сведения.

В CSV ровно восемь столбцов: `path_to_study,study_uid,image_uid,anatomical_region,quality_class,violation_type,processing_status,time_of_processing`; несколько кодов отсортированы и разделены `;`. UID считаются пригодными только после безопасного чтения DICOM. При отсутствии UID нельзя надёжно сгруппировать изображения по исследованию; это ограничение входных данных, а не доказательство принадлежности к одному исследованию. Время HTTP/CLI — результат обработки без сетевой передачи; benchmark включает чтение диска/декодирование, инференс, DTO и CSV, но не загрузку браузером.

## Воспроизводимость, приватность и критерии

Python 3.12, ONNX CPUExecutionProvider, закреплённые зависимости и весовой manifest SHA; 74 Python-файла совпадают с оптимизированным архивом, 22 runtime-файла установлены вне Git. Вход модели живёт только во временном каталоге одного запроса; DICOM и производные изображения не отправляются наружу. Данные/веса/построчные метрики игнорируются Git. Схема моделей и проверка манифеста описаны в [модели](docs/model/index.md) и [развёртывании](docs/start/offline.md). Оценки на 249 размеченных снимках — только development/training, не независимая проверка: [числа и методика](docs/model/metrics.md).

Ограничения исходного задания: проекция **не определяется**; позиционирование и ротация бедра **не разделяются**, анатомическая ROI и сантиметровые отступы **не подтверждены**; модельная точность на независимом наборе неизвестна. Текущий локальный Windows-benchmark оптимизированных весов на 102 исследованиях/255 уникальных development-снимках дал 255/255 `Success`, максимум 15.895 с/исследование (не более трёх кадров), среднее 4.262 с, холодная загрузка 2.6479 с. Граница измерения — локальное чтение, декодирование, инференс, DTO и CSV, без сетевой передачи. Это проверка работоспособности и скорости на одной машине, не независимой точности; прежние цифры относятся к предыдущему архиву. Контейнерный запуск/offline-бандл не подтверждены; для других исследований и оборудования гарантии времени нет. Текущий статус и инструкции: [README](README.md), [руководство](docs/ui/index.md), [развёртывание](docs/start/offline.md).
