# Правила работы с DEXQ

## Принципы

- Пиши минимальный, чистый и прозрачный код для хакатона.
- Не добавляй абстракцию, слой, интерфейс или зависимость без текущей практической причины.
- Не создавай функции на три строки, если они не переиспользуются и не отделяют самостоятельное правило предметной области.
- Не используй repository/UoW/DI-container/CQRS и другие enterprise-паттерны без реальной БД или нескольких реализаций.
- Предпочитай явный список объектов и обычную композицию скрытой регистрации и магии.
- Один файл — одна понятная ответственность, но не дроби связанный код на микромодули.
- Медицинскую эвристику всегда маркируй как эвристику. Не называй результат клинически валидированным без доказательств и метрик.
- Не отправляй DICOM и производные изображения во внешние сервисы.

## Python

- Python 3.12, обязательные type hints для публичного кода.
- Публичные классы и нетривиальные функции документируй Google-style docstring на русском языке: `Args`, `Returns`, `Raises`.
- Комментарии пиши на русском и только там, где нужно объяснить решение или ограничение, а не синтаксис.
- Ошибки на границе API преобразуй в понятные HTTP-ответы; внутри не проглатывай исключения.
- Проверка качества реализует единый контракт `QualityCheck`; модель и preprocessing остаются внутри модуля проверки.
- Результат должен быть детерминированным, сериализуемым и не содержать персональные DICOM-теги.

## React

- TypeScript в строгом режиме, функциональные компоненты.
- Не добавляй глобальный state manager, пока состояния React Router и локального состояния достаточно.
- Не используй UI-kit: сохраняй собственный лаконичный медицинский стиль.
- Основной шрифт — Evolventa, заголовки — Evolventa Bold. Не подменяй их системными шрифтами.
- Компонент выделяй, когда он повторяется или имеет собственное поведение; не создавай обёртки без смысла.
- Интерфейс не должен знать названия моделей и внутреннюю последовательность pipeline.

## Проверка изменений

- Backend: `pytest` и `ruff check .`.
- Frontend: `npm run build`.
- Для изменений API добавляй или обновляй тест контракта.
- Для модельной логики фиксируй версию весов, SHA-256, preprocessing и пороги.
- Не коммить медицинские данные, веса, `.env`, виртуальные окружения и `node_modules`.
