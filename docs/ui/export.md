## Какой отчёт выбрать

<div class="grid cards" markdown>

-   :material-trophy-outline:{ .lg .middle } **Для организаторов**

    ---

    Ровно 8 столбцов из технического задания. Только **автоматический** результат модели — ручные правки сюда не попадают никогда.

-   :material-doctor:{ .lg .middle } **Отчёт врача**

    ---

    Те же 8 столбцов плюс 7 дополнительных: источник оценки, координаты ручной оси, угол и правило. Учитывает **сохранённые** ручные правки.

</div>

Пункты **«Выбранные · для организаторов»** и **«Выбранные · отчёт врача»** выгружают только выделенные снимки. То же делает кнопка :material-download: над списком, когда что-то выделено.

## Столбцы отчёта для организаторов

| Столбец | Пример | Значение |
| --- | --- | --- |
| `path_to_study` | `study_01/img_1.dcm` | Имя файла или относительный путь внутри ZIP |
| `study_uid` | `1.2.826.0.1…` | StudyInstanceUID из DICOM |
| `image_uid` | `1.2.826.0.1…` | SOPInstanceUID из DICOM |
| `anatomical_region` | `lumbar_spine` | `lumbar_spine`, `proximal_femur` или `unknown` |
| `quality_class` | `1` | `0` — норма, `1` — есть нарушение, пусто при ошибке |
| `violation_type` | `spine_axis` | Коды нарушений через `;`, пусто если нарушений нет |
| `processing_status` | `Success` | `Success` или `Failure` |
| `time_of_processing` | `2.3715` | Время обработки, секунды |

Коды нарушений: `spine_positioning`, `spine_axis`, `spine_artifacts`, `hip_positioning_rotation`, `hip_roi`.

## Дополнительные столбцы отчёта врача

| Столбец | Значение |
| --- | --- |
| `assessment_source` | `automatic` — результат модели; `manual_axis_heuristic` — учтена ручная ось |
| `axis_top_x`, `axis_top_y` | Верхняя точка ручной оси в пикселях исходного снимка |
| `axis_bottom_x`, `axis_bottom_y` | Нижняя точка ручной оси |
| `axis_angle_deg` | Угол ручной оси, градусы |
| `axis_rule` | Правило решения: `angle_gt_5_deg` |

Для снимков без ручной правки дополнительные поля пустые, кроме `assessment_source = automatic`.

## Предупреждения перед выгрузкой

Перед отчётом для организаторов DEXQ проверяет проект и предупреждает, если:

- обработка ещё не завершена — в отчёт попадут только готовые снимки;
- в архиве была ошибка — отчёт может быть неполным;
- пути к снимкам повторяются — строки будет трудно сопоставить;
- у обработанных DICOM нет Study UID или Image UID.

Перед отчётом врача DEXQ предложит сохранить несохранённые правки оси. Любое предупреждение можно осознанно пропустить и скачать файл.

## Детали формата

- Одна строка на каждый входной снимок, включая ошибки (`Failure`).
- CSV в кодировке UTF-8 с BOM — Excel откроет кириллицу без настройки.
- Если путь к файлу начинается с `=`, `+`, `-` или `@`, в начало добавляется апостроф: иначе Excel принял бы его за формулу.
- В CSV попадают исходные относительные пути из ZIP. Если имена файлов содержат персональные данные, они окажутся и в отчёте — учитывайте это, прежде чем пересылать файл.
