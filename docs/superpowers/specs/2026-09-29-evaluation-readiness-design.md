# Готовность DEXQ к проверке: согласованное решение

Дата: 2026-09-29. Основание: `требования.pdf` §2.4–2.7, ответ организаторов и подтверждённый пользователем вариант.

## Живая ручная оценка
Две редактируемые точки задают только ось позвоночника. При перемещении немедленно вычисляются угол и предварительный статус `spine_axis` по уже применяемой эвристике «строго больше 5°». Общий статус в редакторе также предварительный: он учитывает неизменные остальные проверки. Проверка `spine_artifacts` производится моделью по пикселям и **не изменяется** от движения точек; результат не называется новым заключением модели. «Сохранить» фиксирует ось в текущем проекте для врачебного отчёта. Исходный автоматический ответ не перезаписывается. Undo, redo и сброс действуют на черновик, обновляя предварительный экран; после сохранения они не меняют сохранённый врачебный отчёт до повторного сохранения.

## Два отчёта
Официальный экспорт «Для организаторов» формирует CSV и XLSX с ровно 8 полями из ТЗ: `path_to_study,study_uid,image_uid,anatomical_region,quality_class,violation_type,processing_status,time_of_processing`. Одна строка на завершённое входное изображение, ошибки обозначены `Failure` с пустым классом; UID берутся только из DICOM. При неполной очереди, ошибке ZIP, повторяющихся путях или отсутствии UID в успешных DICOM перед выгрузкой показывается предупреждение; скачать файл с известным ограничением можно только по явному подтверждению. Поля класса и нарушений отражают автоматическую оценку, даже если врач сохранит ось. Для ZIP `path_to_study` — исходный относительный путь внутри архива, для отдельных файлов — входное имя; пути ZIP не показываются в карточках приложения. Врачебный отчёт CSV/XLSX отдельно включает сохранённый ручной класс и семь дополнительных колонок источника/координат/угла/правила, с явной пометкой `manual_axis_heuristic`. Черновые правки не проникают ни в один файл; если они есть, врачебный экспорт предлагает сперва нажать «Сохранить».

## Вместимость и ошибки
В одном проекте и одном ZIP — не более 1000 изображений. Batch API остаётся ограниченным 200 файлами; размеры одного файла и суммарного распакованного ZIP не меняются. ZIP принимается потоково по результатам, но загружается и держится в памяти целиком: ограничение сжатого архива 1024 МБ сохраняется. Прокси разрешает загрузку в рамках backend-ограничения и не задерживает поток ответа. При превышении лимитов пользователь получает явную ошибку, а неполный поток не выдаётся за успешный. 1000 — предельная вместимость, не гарантия времени обработки или расхода RAM.

## Проверка и публикация
Тесты фиксируют официальный контракт, относительные пути ZIP, UID, границы 1000/1001, неизменность артефактов, выгрузку врачебных правок и сохранность автоматического результата. Браузерная проверка проводится на синтетических файлах и локально обезличенных снимках без отправки данных во внешние сервисы. `pytest`, `ruff check .`, frontend build и тесты обязательны. Отдельно составляется матрица требований PDF с доказательствами и честными ограничениями: закрытый тест и среда экспертов недоступны, поэтому стопроцентную успешность утверждать нельзя. Публикация, push и отправка ссылок не входят в эту реализацию без нового запроса.
