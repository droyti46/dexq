**Дата:** 2026-09-28

## Назначение и границы

Локальный технический MVP помогает оператору обнаруживать нарушения качества DXA на DICOM позвоночника и проксимального отдела бедра, видеть объясняющие наложения, вручную корректировать **только** два центра оси позвоночника и выгружать автоматические результаты в CSV. Это контроль качества, не диагностика и не клинически валидированная система. Успех: при одинаковом исходном DICOM вывод соответствует неизменённому эталонному `QCPipeline.infer()`, интерфейс не подменяет ручной правкой результат ML, пакет выдерживает ошибочный файл, медицинские данные и веса не попадают в новые коммиты или внешние сервисы.

## Подход и альтернативы

**Выбрано:** сохранить исходные inference-файлы `combined_qc` из большого архива без изменения алгоритмов; локально держать его ONNX/NPZ runtime и необходимые конфиги с проверкой SHA-256; тонкий адаптер DEXQ переводит вывод в текущий API. Прямой порт моделей внутрь существующих эвристических `checks` повышает риск незаметно изменить preprocessing; замена hip-модуля отдельным ZIP лишает общий пайплайн воспроизводимости. Устойчивую пакетную обработку и интерфейс реализуем снаружи эталона.

## Источники, файловые границы и безопасность

- Из архива в отслеживаемый исходный код переносятся только необходимые для inference Python-модули, конфиги, схемы хешей, короткие агрегированные метрики и документация; вспомогательное обучение и исходные dataset manifests с идентификаторами не публикуются. Перенесённые исходные модули остаются побайтово идентичны эталону. Веса ONNX/NPZ, DICOM, PNG, тренировочные артефакты и построчные метрики остаются **вне Git**.
- Скрипт локальной подготовки извлекает только разрешённые runtime-файлы, сверяет пути, размеры и SHA-256 с эталонным манифестом, не исполняет код из ZIP, не допускает traversal и не публикует вход. Исходный архив обязателен для установки моделей, но не на каждом запросе. При отсутствии/несовпадении весов сервис явно сообщает о неготовности модели вместо тихого fallback к эвристике.
- Проверить совместимость Python 3.12 и фиксированных зависимостей ONNX runtime (`numpy 2.3.5`, `Pillow 12.3.0`, `scipy 1.18.1`, `onnxruntime 1.30.0`, `pydicom 3.0.2`) с доступным окружением; не менять их молча. Docker монтирует локальные runtime-веса только на чтение, а не скачивает их. Исходный `QCPipeline` загружается один раз на процесс и синхронизирует обращения собственным lock.
- API не сохраняет постоянные исследования. Эталонный runtime принимает пути, поэтому адаптер временно создаёт один входной файл в закрытом локальном временном каталоге, немедленно удаляя его после инференса; никакой сетевой передачи. На API-границе ограничиваются размер, формат, число файлов и архивов, ошибки санитизируются без трассировок и персональных тегов.
- Два архива `data/LCT_data_handoff_2026-09-15*.zip` уже существуют в истории `origin/main` и содержат DICOM. `.gitignore` не удалит их из истории. В текущей задаче новые изображения/веса не коммитить; удаление старых объектов истории и force-push потребуют отдельного решения пользователя.

## Данные для ручного тестирования

Игнорируемый Git локальный каталог `local-test-images/` формируется из **обезличенных** исходных DICOM большого архива по экспертной разметке, не по предсказанию модели. Группы: норма, `spine_positioning`, `spine_axis`, `spine_artifacts`, `hip_positioning_rotation`, `hip_roi`, сочетания нарушений, без экспертной оценки. Одна запись может находиться в нескольких группах; скрипт исключает метаданные и имена, потенциально содержащие ФИО, из генерируемого индекса, назначает нейтральные имена и фиксирует источник и SHA исходного ZIP. Локальный README объясняет «тестовые для поиграться», наличие пересечений, отсутствие независимого теста и запрет публикации. Генерация идемпотентна, проверяет класс на манифесте и не переносит производные снимки в Git.

## Инференс и API

Для `auto` истинным маршрутизатором служит эталонный classifier. Ручное указание области — отдельный явный путь к соответствующему модулю с предупреждением, что маршрут выбран оператором; hip-side всё равно определяет исходная модель. Данные для моделей передаются из исходного DICOM без текущей процентильной нормализации `imaging.py`. Демонстрационные PNG/JPEG поддерживаются только там, где оригинальный runtime действительно принимает их, иначе возвращается 422. DICOM-теги извлекаются лишь из безопасного списка (Study/SOP UID), не из ответного raw payload эталона.

Результаты `spine_positioning`, `spine_axis`, `spine_artifacts`, `hip_positioning_rotation`, `hip_roi` отображаются в единый `QualityCheck`-контракт. Старые `hip_coverage`/`hip_rotation` не выдаются за две самостоятельные модели: эталонный hip positioning/rotation — **одна** мультиметка; прежний контракт и README обновляются без искусственного дублирования. Нарушение итогового OR имеет класс `1`; отсутствие нарушений при всех известных проверках — `0`; `needs_review`, неразрешённая область и неизвестная обязательная проверка дают `null`, если нет уверенно обнаруженного нарушения. В API остаются название, UID, область, class, нарушения, статусы, секунды, машинные scores и provenance; пути, потенциальные персональные метаданные и внутренние `raw` не выдаются.

Существующие одиночный и пакетный endpoints и CSV сохраняют обратную совместимость, кроме документированного сокращения фиктивных hip-классов. Ошибка одного файла становится `Failure`, другие файлы продолжают обрабатываться. Архивный endpoint возвращает строки всех пригодных DICOM в стабильном порядке; безопасно обрабатывает имена и ZIP-лимиты. CSV строго сохраняет колонки задания: `path_to_study`, `study_uid`, `image_uid`, `anatomical_region`, `quality_class`, `violation_type`, `processing_status`, `time_of_processing`.

## Геометрия, визуализация и ручная коррекция

Ответ для результата содержит исходный PNG для просмотра и минимальный DTO геометрии в `native_pixels_x_right_y_down`: размеры кадра, у позвоночника `axis_line` (верхняя/нижняя точки), `vertebral_candidates` и `gap_lines`; у бедра `foreground_bbox` и пояснение о яркостном proxy. Эталонный `annotated_image` можно показывать как статичный контрольный режим, не смешивая с редактируемым наложением. У бедра нет анатомической ROI-сегментации или точек. UI не знает названий моделей, а знает только типы наложений и названия проверок.

На исходном изображении пользователь может перетащить две существующие точки оси позвоночника. Клиент пересчитывает только угол по оригинальной формуле `measure_tilt` (нативные x вправо/y вниз, `atan2(dx, dy)`, вертикальная ориентация, строгий порог `>5°` с оговоркой о точном равенстве). Проверяются конечность координат, границы изображения и положение верхней точки выше нижней. Исходные `checks`, `quality_class` и scores не изменяются: рядом отображается отдельно маркированный ручной пересчёт угла и производный ручной итог OR, остальные автоматические проверки остаются как были. Есть сброс. Если двух точек нет, правка недоступна и причина видима. Поправки живут в текущей браузерной сессии, не хранятся сервером; текущий интерфейс сохраняет снимки в `sessionStorage` вкладки до её закрытия, поэтому после завершения работы оператор закрывает вкладку. Отдельный экспорт ручных поправок содержит идентификатор анализа, координаты, угол, исходный и ручной итог и явно помечен как пользовательская оценка.

## Метрики и честная интерпретация

Агрегированные значения читаются из эталонного `combined_qc/outputs/deployment_metrics.json`, не пересчитываются при загрузке снимка и не смешиваются с другой версией hip. Протокол: 255 изображений, 249 с экспертной оценкой; итоговый OR F1 `0.8221` на всех размеченных, spine F1 `0.8824` на 99, hip F1 `0.7789` на 150. В таблицах отдельно sensitivity/recall, specificity, F1, balanced accuracy, ROC/PR AUC по применимым подзадачам, число позитивных примеров и охват; AUC для булевого OR не определён. Статистика отражает обучение/development и **не является независимой или клинической валидацией**. Если сохранённые записи допускают CI, отдельный локальный воспроизводимый скрипт вычисляет их и сохраняет только агрегаты с описанием метода и единицы ресэмплинга (исследование); иначе отсутствие CI обозначается явно. Dice/IoU без эталонных масок не показывать. Время инференса и долю успешной обработки измерить на заявленной конфигурации, не экстраполировать на H200.

## Проверки, поставка и этапность

1. SHA-256 исходного ZIP, инвентарь разрешённых файлов, целостность и cold-load всех runtime-модулей. Записать версии моделей, пороги, preprocessing, зависимости.
2. На реальных исходных DICOM сравнить исходный `QCPipeline.infer()` и адаптер по маршруту, стороне, labels, scores и OR; тестировать spine и обе стороны бедра, `needs_review` и ошибочные изображения. Контрактные тесты API, UID privacy, CSV, batch и archive; отдельные тесты геометрии и отсутствующих точек.
3. `pytest`, `ruff check .`, `npm run build`, запуск Docker с read-only volume и healthcheck. Браузерная проверка загрузки до трёх файлов, частичных ошибок, мобильного просмотра, перетаскивания точек, сброса и выгрузки.
4. README, руководство пользователя/развёртывания, описание обучения и предобработки, каталог тестовых примеров, известные ограничения, метрики и сценарий демонстрации сверяются с реальной реализацией. Пушить небольшими понятными коммитами после проверки, не добавляя большие данные.

**Риски и честные ограничения:** реальный hip не выдаёт анатомическую ROI-разметку и не доказывает сантиметровые поля; автоматическая корректировка всех меток на бедре невозможна без нового компонента. Ручное изменение оси не меняет исходные ML-решения. Общие метрики архива получены на development/training, не на закрытом тесте. Если запуск эталонных зависимостей или Docker окажется невозможен в текущем окружении, это будет задокументировано как блокер, а не скрыто эвристическим fallback.
