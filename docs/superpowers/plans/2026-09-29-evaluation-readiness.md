# Готовность DEXQ к проверке — план реализации

**Цель:** показать предварительную ручную оценку оси во время движения точек, отделить строгую автоматическую выгрузку от врачебной, сохранить пути ZIP и принять проект/ZIP до 1000 изображений без ложных обещаний производительности.

**Спецификация:** `docs/superpowers/specs/2026-09-29-evaluation-readiness-design.md`.
**Основание:** `требования.pdf`, стр. 7–8 (§2.4–2.7), ответы организаторов от 2026-09-29 и подтверждённое решение пользователя. Для официального файла — одна строка на изображение, восемь колонок в порядке ТЗ, UID из DICOM. Для ручного отчёта — provenance и координаты. Живую оценку показывает только `spine_axis`, не `spine_artifacts`.

## Границы файлов
- `frontend/src/manualAxis.ts` — формирование предварительного/сохранённого вердикта и двух таблиц без изменения исходного ответа модели.
- `frontend/src/projects.ts`, `frontend/src/report.ts` — структура элемента, CSV и Excel.
- `frontend/src/components/ProjectProvider.tsx`, `frontend/src/api.ts`, `frontend/src/types.ts` — поток ZIP, путь для официального экспорта и сохранение черновика оси в памяти вкладки.
- `frontend/src/pages/WorkspacePage.tsx`, `frontend/src/workspace.css` — маркировка предварительного результата и два вида экспорта.
- `backend/app/batch.py`, `backend/app/api.py`, `frontend/nginx.conf` — отдельные лимиты batch=200, ZIP=1000, прокси для больших загрузок/длительного потока.
- `frontend/src/*.test.ts`, `backend/tests/test_api.py`, `backend/tests/test_batch.py` — контрактные и граничные тесты.
- `docs/user-guide.md` — ограничения и инструкция для проверяющих. `docs/deployment.md` не редактировать: сейчас изменён другой сессией.

## Риски и проверки
- Один ZIP свыше 1024 МБ сжатого объёма остаётся неподдерживаемым.
- 1000 полноразмерных превью в памяти вкладки и длительный поток пока не имеют подтверждённого профиля памяти/времени — требуется ограничение обещаний.
- Путь ZIP может содержать персональные данные: скрыт в UI, присутствует в скачиваемом файле только по действию пользователя, не отправляется наружу.
- Исходные DICOM UID могут отсутствовать; нельзя изобретать их или обещать, что закрытый тест не содержит таких случаев.
- Отсутствие PDF sample_submission и закрытого набора исключает гарантию успешной автопроверки; контракт проверяется против текста ТЗ и ответа организаторов.
