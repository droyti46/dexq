# Работа с DEXQ

DEXQ — локальный исследовательский инструмент контроля качества DXA, **не** диагностическая система. Используйте обезличенные DICOM; медицинские файлы и производные изображения не передавайте во внешние сервисы.

## Подготовка и запуск

Для локального запуска необходим оптимизированный архив `dxa_qc_with_models (2).zip` (SHA-256 `b92ed6e89b1bb54358b1e06681842dbecac006880cf9062ea68980673ff12f0a`): установите его по [инструкции развёртывания](deployment.md), затем запустите backend и frontend. До доступности моделей `/api/v1/health` отвечает 503; fallback на другую модель не предусмотрен. Исходный архив и установленный каталог моделей хранятся вне Git. Локальный набор для ручных опытов можно создать из того же архива: из `backend/` выполните `python ../scripts/prepare_samples.py "/path/to/dxa_qc_with_models (2).zip" --output ../local-test-images`. Папки разложены **по экспертным классам, не по ответам модели**; снимок с несколькими нарушениями находится в нескольких папках. 255 DICOM остаются только локально.

## Анализ в браузере

1. На главной нажмите «Попробовать демо» — откроется список проектов. Создайте проект с названием и добавьте до 200 DICOM, PNG или JPEG (изображения для технической демонстрации) либо **один ZIP** с DICOM/PNG. Одиночные JPEG преобразуются в PNG локально; JPEG внутри ZIP текущая модель не поддерживает. Архив добавляйте отдельно от обычных файлов; суммарно в проекте не более 200 снимков. Можно перетащить новые файлы в левую панель или viewer — они добавятся, не заменяя предыдущие. Анатомическая область определяется автоматически. Норматив `≤180 с` локально пройден для исследований из 1–3 снимков на development-наборе, но для больших исследований и другого оборудования не проверен.
2. После обработки откройте карточку снимка. Для каждого файла сохраняется отдельный статус `Success` или `Failure`; ошибки отдельных файлов не скрывают успешные результаты. `Success` всегда содержит бинарный класс: `0` без выявленных нарушений и `1` при хотя бы одном из применимых нарушений. Если обязательная оценка неизвестна, статус `Failure` и пустой класс в CSV. Даже при `Success` предупреждение `needs_review` требует экспертного внимания.
3. Просмотрите снимок и ориентиры; наложение включено по умолчанию и переключается кнопкой слоёв или через «Редактор». Колесо масштабирует относительно курсора, перетаскивание перемещает изображение, включая правую и среднюю кнопки; двойной клик вписывает снимок. «Сбросить вид» возвращает масштаб, яркость, контраст и наложение по умолчанию, не сбрасывая ручную ось. На позвоночнике редактируются **только две реально найденные точки**: включите инструмент редактирования ориентиров и перетащите точку либо перемещайте фокусированную точку стрелками. Ручной угол — **отдельная эвристическая оценка** с порогом 5°, автоматический ответ не меняется. `Ctrl/Cmd+Z` отменяет правку, `Ctrl+Y` или `Ctrl/Cmd+Shift+Z` возвращает; одно перетаскивание — одна операция. «Сбросить ручную ось» тоже отменяется.
4. Выбирайте снимки чекбоксами, `Ctrl/Cmd` по клику, `Shift` для диапазона или рамкой перетаскивания в левой панели. Клавиша `Del` или действие «Удалить выбранные» открывает подтверждение; удаление требует подтверждения и не удаляет исходные файлы на устройстве. В «Файл» доступны экспорт отчёта CSV и настоящий Excel `.xlsx`, включая экспорт выделенных; выгружаются завершённые файлы, в том числе ошибки. Отчёт содержит автоматические результаты, не ручные поправки.
5. На широком экране перетаскивайте разделители между панелями для изменения ширины; двойной клик возвращает ширину по умолчанию. При открытом верхнем меню наведение на соседнее переключает его. Очередь продолжает работу при возврате в список проектов. Проценты во время анализа **приблизительные**, 100% появляется только после завершения.
6. Проекты, файлы, результаты и история правок находятся **только в памяти текущей вкладки**. Переходы по приложению их сохраняют; обновление или закрытие вкладки очищает всё. Сохраните отчёт заранее. Медицинские изображения не записываются в постоянное браузерное хранилище.
7. Для бедра бирюзовая рамка — граница **яркостного поля**, не анатомическая ROI-маска; анатомических точек для ручной корректировки эталон не предоставляет. Проверка `hip_positioning_rotation` объединяет позиционирование и ротацию; система не различает их автоматически.

Проекция не размечена в исходном наборе: отображается «не определена». Не делайте вывод об AP/PA по анатомической области, стороне или форме кадра. DICOM с явно другой стандартной проекцией отклоняется как неподдерживаемый; повторно проверьте исследование вручную.

## Пакет, CSV и локальные примеры

- `POST /api/v1/analyses/batch` принимает до 200 файлов, `POST /api/v1/analyses/batch.csv` возвращает CSV для того же пакета; `POST /api/v1/analyses/archive` принимает ZIP и возвращает JSON, `/archive.csv` принимает тот же ZIP и возвращает CSV. CLI: из `backend/` запустите `python -m app.cli /path/to/studies.zip /local/path/results.csv`.
- CSV содержит ровно `path_to_study,study_uid,image_uid,anatomical_region,quality_class,violation_type,processing_status,time_of_processing`. Одна строка на изображение, типы нарушений в стабильном порядке через `;`, класс пуст при `Failure`; четвёртый и последующие кадры одного StudyInstanceUID обрабатываются без отсечения. В JSON поле `input_position` (с единицы) различает одинаковые имена файлов без раскрытия путей из архива; CSV сохраняет исходные относительные пути и может содержать чувствительные имена. В интерфейсе список снимков прокручивается; CSV и Excel экспортируются локально из уже полученных результатов, без повторного анализа. ZIP-пути не раскрываются в интерфейсе.
- Из папки `local-test-images/normal` удобно начать с примеров без экспертных нарушений, из `spine_axis` — с ручного пересчёта угла, из `multiple` — с одновременных нарушений. Примеры **не** служат независимым тестом качества модели, поскольку снимки этого development-набора использовались для обучения или настройки правил. Не загружайте содержимое этой папки, PNG-превью и CSV с UID в репозиторий.

При ошибке формата проверьте исходный DICOM и повторите загрузку; если модели недоступны, проверьте локальный манифест/веса. Статистика и ограничения: [метрики](metrics.md), [модель](model.md), [развёртывание](deployment.md).
