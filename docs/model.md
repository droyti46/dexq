# Эталонная модель и границы интерпретации

**Источник единственный:** `dxa_qc_with_models.zip` (SHA-256 `2cd75f3777a4a7735d8e36cca371d4637b54053fb9283863c64c7214535a8867`), финальное собранное решение команды. Исходники `backend/reference/combined_qc/` оставлены побайтово неизменными. Скрипт `scripts/prepare_reference.py` устанавливает проверенные 34 runtime-файла локально в `backend/models/reference/`; манифест их хешей привязан к SHA исходной поставки. Отдельные архивы hip, notebook-веса и файлы обучения **не** смешиваются с этим релизом. Версии Python/библиотек и базовых образов см. [развёртывание](deployment.md).

## Цепочка инференса

Один загруженный `combined_qc.router.QCPipeline` автоматически определяет **анатомическую область** (spine/hip). После этого spine и hip-модули запускают независимые применимые проверки; для бедра сторона определяется отдельным пиксельным классификатором. Ручной выбор области в API минует router, но использует исходный профиль области и его веса. ONNX выполняется локально через `CPUExecutionProvider` с постоянными весами на процесс и синхронизацией вызовов. Временный исходный файл используется только потому, что неизменённый runtime принимает путь; после каждого вызова он удаляется. Сервер не хранит исследование и ручные исправления.

- Позвоночник: `spine_positioning` — две детерминированные ветки по яркости и последовательности межпозвоночных промежутков; это **эвристика**, не доказанная идентификация Th12/подвздошной кости. Порог нижней ветки `-0.01941480441018939`, верхней `-4.228571428571429` (исходный `spine/engine/coverage.py`); верхняя ветка не назначает уровня позвонка. `spine_axis` — ONNX SpineNet с прямым bilinear resize **всего** нативного кадра до 512×512, повторением grayscale в три канала, нормализацией `float32/255 - 0.5`, пиками heatmap ≥0.2 и переносом центров в исходные пиксели. Угол по верхнему и нижнему центрам измеряется `abs(atan2(top.x - bottom.x, bottom.y - top.y))` в градусах; нарушение строго при `>5°`, равенство с допуском `1e-10` не считается нарушением. Отсутствие двух центров даёт неопределённое решение. `spine_artifacts` — фиксированный ResNet18 feature extractor, морфологические признаки и один числовой классификатор с порогом 0.5.
- Бедро: нативный одноканальный 8-bit grayscale DICOM `MONOCHROME2` или grayscale PNG; bilinear letterbox до 320×320 с чёрной рамкой, `float32 / 255`. Качество использует пять ONNX-folds для позиционирования/ротации и пять для охвата, с порогами из оригинальных runtime JSON (веса и калибровка закреплены SHA в манифесте). Правый hip зеркалируется для признаков позиционирования, сторона получается из отдельной модели, а не из имени файла. `hip_positioning_rotation` — **единый** флаг: разделить позиционирование и ротацию он не способен. `hip_roi` оценивает обученную задачу охвата по фиксированным областям и геометрическим признакам; `foreground_bbox` на картинке — яркостная рамка, **не** анатомическая сегментация и не измерение запаса поля в сантиметрах.
- Итоговый `quality_class=1` при хотя бы одном нарушении, `0` только когда **все** обязательные применимые метки определены и равны `False`; при неизвестном обязательном решении статус `Failure` и класс пуст. Предупреждение `needs_review` выводится независимо от бинарного результата. Проекция не обучалась и не выводится по стороне/области: `projection=unknown`, `projection_source=not_determined`; известная неподдерживаемая ViewPosition отклоняется.

Исходная предобработка DICOM сохраняет исходные uint8-пиксели, без произвольного клинического windowing или смены полярности. Для неподдерживаемых фотометрических форматов/битности или повреждённых файлов не существует эвристического fallback. Ручной сдвиг двух реально обнаруженных точек позвоночника пересчитывает только отдельный клиентский угол; модельный вывод и пороги не меняются.

## Обучение, данные и ограничения

Исходный архив включает код обучения, однако приложение его не запускает и веса при обслуживании не дообучаются. Эталонный hip использует агрегирование пяти folds для качества; классификатор артефактов spine обучен на всех 99 размеченных spine-изображениях. Каталог исходных 255 снимков содержит 102 исследования; экспертный QC-итог есть для 249 изображений. Часть снимков использовалась для обучения/подбора порогов, поэтому сравнение модели с экспертной разметкой того же набора **не** является out-of-fold, независимой или клинической валидацией. Подробные агрегаты, интервалы по study и ошибки см. [метрики](metrics.md). Проекция, анатомическая ROI-сегментация, отдельная классификация ротации и клинически значимая калибровка остаются вне фактически поставленного решения. Для пилотирования нужны новые обезличенные исследования, независимая экспертная оценка и заранее зафиксированные пороги.
