# Тесты и проверки

<p class="lead">Перед каждым коммитом запускайте три команды: тесты backend, линтер и сборку frontend. Все они работают без сети и без медицинских данных.</p>

## Быстрый прогон

=== "Backend"

    ```bash
    cd backend
    .venv/bin/python -m pytest
    .venv/bin/python -m ruff check .
    ```

=== "Frontend"

    ```bash
    cd frontend
    npm run build
    node --experimental-strip-types --test src/*.test.ts
    ```

=== "Документация"

    ```bash
    pip install -r docs/requirements.txt
    mkdocs serve
    ```

    Сайт документации откроется на <http://127.0.0.1:8000> — если там уже работает сервер DEXQ, добавьте `-a 127.0.0.1:8001`.

Ожидаемый результат на момент написания: `67 passed, 1 skipped` в pytest, `All checks passed!` в ruff, успешная сборка Vite и все 9 файлов тестов frontend зелёные.

## Что проверяют тесты backend

| Файл | Что проверяет |
| --- | --- |
| `test_api.py` | Контракт HTTP: коды ответов, поля JSON, лимиты размера и числа файлов, NDJSON-поток, CSV |
| `test_analysis_contract.py` | Правила итога: бинарный класс при `Success`, `Failure` без решения по оси, общий флаг бедра, проекция только из `ViewPosition`, очистка имён файлов и текста ошибок |
| `test_batch.py` | Безопасность ZIP (опасные пути, дубликаты, лимит 1000 файлов), потоковое чтение, формат CSV, защита от формул, CLI на папке |
| `test_model_runtime.py` | Готовность без моделей, удаление временного файла, отказ для неподдерживаемого формата |
| `test_reference_setup.py` | Установка весов: SHA архива, обход путей, дубликаты и символьные ссылки, проверка хешей моделей |
| `test_reference_parity.py` | Совпадение с эталоном на исходных снимках. **Пропускается**, если не задан `DEXQ_REFERENCE_ZIP` |
| `test_deployment.py` | `run.sh` не запускает Docker без моделей, с повреждённой или чужой поставкой; веса монтируются только для чтения |
| `test_submission.py` | Офлайн-комплект содержит только исходники, модели и сохранённые образы; без образов не собирается |
| `test_benchmark.py`, `test_samples_metrics.py` | Скрипты замера времени и метрик |

Модель в большинстве тестов подменяется заглушкой с тем же контрактом (`ReferenceRuntime(pipeline=...)`), поэтому тесты идут секунды и не требуют весов.

Проверка на реальных снимках из архива:

```bash
DEXQ_REFERENCE_ZIP="/путь/к/dxa_qc_with_models (2).zip" .venv/bin/python -m pytest tests/test_reference_parity.py
```

## Правила проекта

- **Изменили API — обновите контрактный тест** в `test_api.py` или `test_analysis_contract.py`.
- **Изменили модельную логику — зафиксируйте** версию весов, SHA-256, предобработку и пороги в [описании модели](../model/index.md).
- **Не коммитьте** медицинские данные, DICOM, PNG-превью реальных снимков, веса (`*.onnx`, `*.npz`), `.env`, виртуальные окружения и `node_modules`. Большая часть этого уже в `.gitignore`.
- Медицинские эвристики помечайте как эвристики — в коде, интерфейсе и отчётах.

## Стиль кода

| Часть | Правила |
| --- | --- |
| Python | 3.12, type hints для публичного кода, docstring в стиле Google на русском (`Args`, `Returns`, `Raises`), `ruff` с длиной строки 100 |
| TypeScript | Строгий режим, функциональные компоненты, без UI-kit и глобального state manager |
| Комментарии | На русском и только там, где нужно объяснить решение или ограничение |
