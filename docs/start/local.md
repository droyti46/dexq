# Запуск без Docker

<p class="lead">Сервер и сайт запускаются в двух отдельных терминалах. Этот способ удобен для разработки: сайт перезагружается сам при изменении кода, а сервер можно перезапустить за секунду.</p>

## Требования

- Python **3.12** (3.13 пока не поддерживается: `requires-python = ">=3.12,<3.13"`);
- Node.js **22** и npm;
- распакованный архив DEXQ — веса моделей в нём [уже на месте](weights.md).

## Терминал 1 — сервер анализа

<div class="steps" markdown>

1. **Создайте виртуальное окружение и установите зависимости:**

    === "Linux / macOS"

        ```bash
        cd backend
        python3.12 -m venv .venv
        .venv/bin/python -m pip install -e ".[dev]"
        ```

    === "Windows"

        ```powershell
        cd backend
        py -3.12 -m venv .venv
        .venv\Scripts\python -m pip install -e ".[dev]"
        ```

2. **Запустите сервер:**

    ```bash
    .venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
    ```

    Для разработки добавьте `--reload` — сервер будет перезапускаться при сохранении файлов.

3. **Проверьте** <http://localhost:8000/api/v1/health> — должен прийти `{"status":"ready",…}`. Первая проверка загружает модели и занимает несколько секунд.

</div>

## Терминал 2 — сайт

<div class="steps" markdown>

1. **Установите зависимости** из корня репозитория:

    ```bash
    npm --prefix frontend ci
    ```

2. **Запустите сервер разработки Vite:**

    ```bash
    npm --prefix frontend run dev
    ```

3. **Откройте** <http://localhost:3000>. Все запросы к `/api` Vite перенаправляет на `http://127.0.0.1:8000`, поэтому отдельная настройка адреса сервера не нужна.

</div>

## Без сайта: пакетная обработка из командной строки

Если нужен только CSV с результатами, сервер и сайт запускать не обязательно:

```bash
cd backend
.venv/bin/python -m app.cli /путь/к/studies.zip /путь/к/results.csv
```

На вход подойдёт ZIP-архив, папка или отдельный файл. Подробности — в разделе [CSV и CLI](../api/csv.md).

## Сборка сайта для продакшена

```bash
npm --prefix frontend run build
```

Готовая статика появится в `frontend/dist/`. Её может раздавать любой веб-сервер; запросы `/api/` нужно проксировать на сервер анализа — пример в `frontend/nginx.conf`.

!!! note "Где хранятся данные"
    Сервер не сохраняет снимки: файл обрабатывается в памяти, временная копия для модели удаляется сразу после анализа. Проекты на сайте живут только в памяти вкладки браузера — после её закрытия или обновления они исчезают.
