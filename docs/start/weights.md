# Веса моделей

<p class="lead">В архиве DEXQ веса уже установлены в папку <code>backend/models/reference/</code>. Делать с ними ничего не нужно — эта страница объясняет, как они проверяются и что делать, если проверка не прошла.</p>

## Что лежит в папке

| Параметр | Значение |
| --- | --- |
| Папка | `backend/models/reference/` |
| Содержимое | 22 файла нейросетей (ONNX), коэффициентов классификаторов (NPZ) и конфигурации, ~264 МиБ |
| Манифест | `installed-manifest.json` — SHA-256 каждого файла |
| Источник | Эталонный архив `dxa_qc_with_models (2).zip`, SHA-256 `b92ed6e89b1bb54358b1e06681842dbecac006880cf9062ea68980673ff12f0a` |

## Как веса проверяются

Проверка выполняется дважды:

1. **До запуска контейнеров** — скрипт `scripts/run.sh` сверяет каждый файл с манифестом. Если что-то не так, Docker не запускается, а в консоли видно, какой файл не совпал.
2. **При старте сервера** — `ReferenceRuntime` повторяет проверку перед загрузкой моделей. Это защищает и запуск без `run.sh`, например `docker compose up` на Windows.

Если проверка не прошла:

- `GET /api/v1/health` отвечает `503 Локальный комплект моделей недоступен`;
- анализ возвращает ошибку, а не результат другой модели — запасного варианта нет намеренно.

**Что делать:** распакуйте архив DEXQ заново — скорее всего, файлы повредились при копировании или распаковка прервалась.

## Веса в другой папке

Если веса хранятся отдельно от кода, укажите абсолютный путь в переменной `DEXQ_MODELS_DIR`:

```bash
DEXQ_MODELS_DIR=/data/dexq/models ./scripts/run.sh
```

??? info "Для разработчиков: установка весов в чистую копию из GitHub"
    В Git-репозитории весов нет. Чтобы установить их из эталонного архива, из папки `backend/` с установленными зависимостями выполните:

    ```bash
    .venv/bin/python ../scripts/prepare_reference.py "/путь/к/dxa_qc_with_models (2).zip"
    ```

    Скрипт проверит SHA-256 архива, извлечёт только нужные 22 файла и запишет манифест. В конце появится строка `Проверено 22 файлов runtime; веса остаются локальными.`
