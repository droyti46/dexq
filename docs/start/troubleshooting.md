# Если что-то не так

<p class="lead">Самые частые проблемы при запуске и что с ними делать.</p>

??? failure "`/api/v1/health` отвечает 503 «Локальный комплект моделей недоступен»"
    Сервер не нашёл веса или контрольная сумма какого-то файла не совпала.

    1. Проверьте, что папка `backend/models/reference/` существует и в ней есть `installed-manifest.json`.
    2. При запуске через `docker compose` без `run.sh` убедитесь, что задана переменная `DEXQ_MODELS_DIR` с **абсолютным** путём к этой папке.
    3. Распакуйте архив DEXQ заново — файлы могли повредиться при копировании.

??? failure "`Проверка моделей не пройдена` при запуске `run.sh`"
    Скрипт проверил веса до запуска Docker и нашёл расхождение: какой-то файл изменён или отсутствует. Распакуйте архив DEXQ заново. Другие версии весов DEXQ не принимает намеренно.

??? failure "Сайт открывается, но снимки не обрабатываются («Не удалось выполнить анализ»)"
    Сайт не достучался до сервера.

    - **Без Docker:** проверьте, что сервер запущен на `127.0.0.1:8000` — именно туда Vite перенаправляет `/api`.
    - **В Docker:** посмотрите `docker compose logs backend`. Контейнер `frontend` не стартует, пока `backend` не станет `healthy`.

??? failure "У снимка статус «Ошибка»"
    Файл не удалось безопасно прочитать или модель не дала решения по всем обязательным проверкам. Частые причины:

    - файл повреждён или это не DICOM;
    - формат не поддерживается: цветной снимок, 16-битные пиксели, не `MONOCHROME2`;
    - в DICOM явно указана проекция, отличная от AP/PA;
    - модель не уверена в области снимка (уверенность роутера ниже 0,9) — такой снимок помечается «нужна проверка», и итог не выставляется.

    Остальные снимки проекта это не затрагивает — ошибка относится только к одному файлу.

??? failure "`python3: command not found` при запуске `run.sh`"
    Скрипту нужен любой Python 3 для проверки весов. Установите его или укажите путь: `PYTHON=/usr/bin/python3 ./scripts/run.sh`. На Windows используйте команду `docker compose up --build` из раздела [Запуск в Docker](docker.md) — там Python не нужен.

??? failure "Порт 3000 или 8000 занят"
    Остановите процесс, который занимает порт, или поменяйте проброс портов в `docker-compose.yml` (`"3001:80"`, `"8001:8000"`). Без Docker — запустите uvicorn с `--port 8001` и поправьте адрес в `frontend/vite.config.ts`.

??? failure "Большой ZIP обрывается по таймауту"
    Nginx ждёт ответа до 300 секунд. На слабой машине архив в 1000 снимков может обрабатываться дольше — разбейте его на части или увеличьте `proxy_read_timeout` в `frontend/nginx.conf`.

Не нашли свою проблему? Отправьте проблемный файл в Swagger (<http://localhost:8000/docs>, метод `POST /api/v1/analyses`) — в поле `detail` ответа будет причина отказа.
